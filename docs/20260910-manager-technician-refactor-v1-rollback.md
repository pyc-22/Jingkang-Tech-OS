# 20260910-manager-technician-refactor-v1 回滚指南

## 回滚前提

本版本包含 V89 数据迁移，会重算历史订单营业日，并同步退款、订单相关会员流水和提成记录。发布前必须同时备份数据库、静态目录和 JAR；只恢复旧 JAR不会恢复迁移前的营业日分布。

## 应用文件回滚

适用于页面资源异常或应用代码故障，但确认保留 V89 修正后的数据：

1. 停止 Web 和 API 服务，暂停新的业务写入。
2. 保存故障日志、浏览器网络记录、当前 JAR 和文件哈希。
3. 从部署前备份恢复完整静态目录和旧 JAR，不改外部配置、附件或数据库。
4. 启动 API 和 Web，检查健康端点、三端登录页及既有核心流程。
5. 注意旧代码若仍按旧营业日逻辑写入新订单或退款，会重新产生错位数据，因此这种回滚只适合作为短时止损。

## 完整版本回滚

需要恢复部署前数据分布时，在维护窗口执行：

1. 停止所有会写数据库的应用实例。
2. 确认部署后没有需要保留的新订单、退款、会员资金或提成记录；如有，先制定并演练数据合并方案。
3. 使用部署前已验证的数据库备份整体恢复到独立数据库，核对恢复点和行数后再切换连接。
4. 恢复部署前静态目录、JAR 和外部配置。
5. 启动旧版本并完成健康、登录、派单、接单、结算、退款和日报回归。

V89 不创建备份表或永久函数，也没有向下迁移脚本。不要删除或编辑已经执行的 Flyway 记录，不要手工反向推算营业日；精确数据回滚以部署前数据库备份为准。

## 回滚后核验

- 健康端点和数据库状态正常。
- 三端静态资源无 404，浏览器控制台无新增错误。
- 房间、技师和待结算状态与回滚点一致。
- 会员余额与流水、订单与支付、退款与原订单、提成与订单记录保持配对。
- 记录恢复使用的备份标识、JAR SHA-256、静态目录哈希、操作人和时间。
