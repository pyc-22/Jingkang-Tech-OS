# 20260911-p0-conflict-fix-v1 回滚指南

## 回滚范围

本版本没有新增数据库迁移，常规回滚只切回上一版静态文件和 JAR。V87、V88、V89 属于上一完整版本，回滚本次 P0 修复时保留这些迁移和现有业务数据。

## 触发条件

- 健康检查不是 `UP` 或发布号不匹配。
- 换项目、派钟、房态、清洁或结算出现新阻断。
- 错误率、数据库锁等待或线程占用显著异常。

## 操作步骤

1. 暂停入口流量和所有写操作。
2. 保存本版本 API/Web 日志、健康响应和故障请求的 operation ID。
3. 停止本版本 Web 和 API。
4. 从部署前备份恢复完整静态目录和上一版 JAR，不混用新旧前端资源。
5. 保留生产环境变量、数据库、附件和日志目录。
6. 用 JDK 21 启动上一版 API 和 Web。
7. 检查上一版健康号并执行关键烟测，再恢复流量。

## 回滚后核对

- 前台、店长端、技师端页面和核心资源返回 200。
- 上一版健康检查和数据库连接正常。
- V87/V88/V89 仍为成功状态。
- 抽查回滚窗口内的派单、房态、退款、结算和离线回执，确认没有半完成业务。
- 对 `PROCESSING` 回执逐条核对对应业务结果，不批量删除或重放。

## 数据处理

本次没有新增表、列或迁移，因此不执行结构回滚 SQL。若确需恢复业务数据，只能从部署前备份按审批流程恢复；不要为了代码回滚覆盖整个生产数据库。
