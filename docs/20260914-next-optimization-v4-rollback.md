# 20260914-next-optimization-v4 回滚指南

## 触发条件

- 健康检查未返回 `UP` 或版本不是 `20260914-next-optimization-v4`。
- 派单恢复、技师开始服务或结算主流程出现阻断。
- Flyway V93 执行失败。

## 应用回滚

1. 停止新版本服务并隔离流量。
2. 保存故障日志、当前数据库状态和失败请求信息。
3. 从部署前备份恢复上一版 JAR 与完整前端目录。
4. 启动上一版服务，确认健康检查和核心业务恢复。
5. 抽查派钟、上钟、下钟、结算、会员余额与日报。

包内 `DEPLOY.ps1` 在切换失败时会恢复其创建的文件备份；数据库仍应使用部署前独立备份作为最终恢复依据。

## 数据库说明

V93 只执行 `service_session.room_id DROP NOT NULL`，不删除或改写数据。应用回滚到 v3 时可保留 V93 及其 Flyway 记录，旧流程仍会继续写入房间。已经生成的无房手工服务属于有效业务记录，不应为恢复 `NOT NULL` 而删除。

如需数据库时间点恢复，应整体恢复部署前数据库备份，并同时恢复与该时间点一致的 JAR 和前端；不要单独修改 Flyway 历史表。
