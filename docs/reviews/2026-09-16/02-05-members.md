# 第二阶段 / 会员

范围：MemberController、MemberRechargeRefundController、WalletTransactionController、订单消费/退款/收款更正中的钱包写入、V8/V12/V59/V60。
后端路径前缀：`services/massage-api/src/main/java/com/chengxin/massage/`。

## 业务不变量

会员和钱包在租户内跨店共享；流水必须保留交易门店，不能拿钱包开户门店限制其他门店消费。充值/消费/退款整体事务，钱包行锁防止同一钱包覆盖更新。
每条流水应满足 `balance_after_cents = balance_before_cents + amount_cents`；钱包余额应与完整流水净额/可信期初余额一致。不同交易相同 created_at 时不能随意按 UUID 排序断言余额链连续。

## R03 / P1：充值退款额度竞争

- 位置：`member/MemberRechargeRefundController.java:66`、`:70`、`:73`、`:99`。
- 两个事务分别读取原充值 100 元和已退 0，各申请 80 元，用不同 request_key 都可插入。若钱包另有余额，两笔完成时仅总余额校验均可通过。
- 唯一 request_key 只能阻止同键重复，不能限制不同键的累计金额。
- 修复：锁原充值记录后查额度；请求键幂等检查纳入同一锁序；完成时重验累计已完成+本次金额。覆盖两用户两会话而不是同 token 测试。

## R04 / P1：退款本金流水的余额快照错误

- 位置：`member/MemberRechargeRefundController.java:99`、`:104`、`:107`。
- 例：余额 120，退本金 100 并收回赠送 20。主行记录 amount=-100、before=120、after=0，算式应为 20；下一赠送行才应从 20 到 0。
- 钱包最终余额可以正确，但流水不可审计。应修正主行中间余额，存量仅修有充分关联证据的快照，禁止按错误快照再扣一次钱包。

## R05 / P1：赠送额以时间邻近猜关联

- 位置：`member/MemberRechargeRefundController.java:66`。
- 同会员两次充值间隔不超过 2 秒时，后一笔 BONUS 可被前一笔退款计入；created_at 使用事务起始时间也会增加歧义。
- 修复：充值和赠送共用操作 ID，退款关联原操作；历史歧义列清单，不能按近邻自动回写。

## 共享风险与异常

- R06：充值幂等键不校验请求体，第二次改变金额仍当重放；开卡不在支持路径清单中。
- R01：会员姓名从录入流向店长跨店流水，形成存储型注入数据链。
- R14：不存在充值退款 ID 返回 .single() 数据访问异常；大金额输入缺统一上界/Math.addExact，可能 500 而非明确 4xx。数据库非负约束会阻止一部分溢出，但不是输入验证。
- 新会员编号用 System.currentTimeMillis，毫秒内并发开卡有唯一键冲突机会；数据库能防重复，但缺重试/友好 409，列 P2 运维改进，不声称会覆盖旧会员。

## 测试重点

开卡含赠送、同店/跨店充值、余额不足结算回滚、混合支付退款、部分充值退款、取消退款释放额度、两人并发退同一充值、重复 request_key、相同幂等键不同内容、赠送余额流水守恒。

第三阶段已复现 R03/R04/R05 和 R06 请求内容问题。正常开卡、零额拒绝、重复会员、退款取消与重复完成、余额不足补单回滚通过；详细数值与尚缺矩阵见第三阶段报告。
