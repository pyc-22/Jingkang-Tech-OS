# 费用报销本地版本与同步修复

版本：`20260919-expense-sync-fix-v1`

## 根因与修复

- 本地 `5188` 提供费用报销新版页面，但其代理的 `8080` 运行的是项目根目录旧 JAR，健康检查版本为 `20260913-next-optimization-v2`。旧后端没有分页接口，店长端 `/api/v1/expense-claims/page` 被旧的 `/{id}` 路由接收，UUID 转换返回 400。财务端同样依赖新版分页接口。修复需同步更新前端和实际运行的 JAR，单独更新页面或源码不足以生效。
- 两端默认日期在页面初始化后固定；手机还把默认日期持久化，跨天后会遗漏新一天的申请。新增默认日期模式，最近 30 天随日期滚动；自定义历史日期保持原值。手机可点击“最近 30 天”恢复默认范围。旧版已存日期按自定义范围保留，避免覆盖用户的历史筛选。
- 日期或门店范围变化后，手机加载更多从第一页重新开始，避免混入旧范围记录。
- 后端健康检查增加 `expenseClaimPaging` 标识。报销请求遇到 400/404 时核对能力，旧后端给出明确的版本不一致提示；真实参数错误和权限错误继续保持原含义。财务轮询失败显示同步错误，避免旧列表仍标记为同步成功。

没有新增数据库迁移；由上一版升级仍使用 V100 的两个报销查询索引。

## 验证方式

前端 198 项、后端 179 项、PostgreSQL/API/浏览器 61 项回归通过。Java 21 JAR 构建成功。

- 单元回归：旧后端诊断、参数及权限错误、最近 30 天跨天滚动、自定义日期持久化、分页重置。
- 真实 PostgreSQL/API 回归：中文和英文请求日期、统计一致性、权限、批量审核、导出及现有业务流程。
- 双浏览器回归：390px 中文店长页面打开费用，保存并提交带凭证报销，财务页面通过正常 20 秒轮询看到新单；财务审核后店长刷新看到已审核状态。旧 JAR 的响应通过本地路由模拟，业务流程使用完整新版 API。

## 运行版本核对

发布时同时使用包内 `apps/massage-console` 和 `services/massage-api/target/massage-api-0.1.0.jar`。备份现有数据库、JAR 和附件，保持数据库连接及附件目录配置，停止旧 API 后启动新版。

访问实际前端端口的 `/api/health`，应同时满足：

```json
{"status":"UP","release":"20260919-expense-sync-fix-v1","expenseClaimPaging":true}
```

检查进程的 `-jar` 路径，尤其注意项目根目录同名旧 JAR。刷新两个浏览器的页面；保留的历史筛选若不覆盖今天，点击“最近 30 天”或财务“重置”后查看新提交的单据。
