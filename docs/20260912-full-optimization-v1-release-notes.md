# 20260912-full-optimization-v1 发布说明

## 发布结论

这是基于当前完整工作树的综合优化版本。打包时必须使用工作树中重新构建的 JAR，保留日报 Bug1/2/3/6、V87/V88/V89、技师端 403、P0 400/409 冲突修复，以及本次 7 项需求的前端、考勤和历史补单改动。

## 需求变更

- 前台左下角显示当前登录用户名/角色，提供个人信息、修改密码和退出登录操作；退出时清理本地会话并跳转登录页。
- 前台结算单隐藏待处理换房和待处理事件区域，保留房间状态与技师队列；后端相关接口继续保留。
- 房间卡片采用 auto-fill 网格、150px 最小宽度、430px 最大高度和内部滚动；房间号、床位/状态、技师姓名和操作按钮字号已放大，主要操作按钮保持至少 44px 触控高度。
- 店长端新增安排技师上钟对话框，复用 `/api/v1/service-sessions/clock-in` 与预约/加钟 API，支持钟类、项目、房间、技师轮钟推荐/手选和业绩分配。
- 技师端改为被动接单；自主上钟入口和离线写请求移除，后端移动端 clock-in 先校验会话后固定返回 403，不创建服务、房间或审计业务记录。
- 新增技师营业日打卡/下班打卡、状态和已打卡技师查询；历史未打卡技师按兼容规则处理。
- 新增历史补单权限、管理员授权/撤销、补单订单标记、营业日统计适配和审计查询；V91 为追加式迁移。

## 历史修复完整性

- 日报 Bug1：日报金额使用 `orders.salesAmountCents()`，净额独立计算。
- 日报 Bug2：日报服务单统计不再错误排除三处 VOIDED 关联条件。
- 日报 Bug3：退款 `business_date` 继承原订单营业日。
- 日报 Bug6：订单营业日使用 `businessClock.businessDate(storeId, settledAt)`，列表按 `o.business_date` 筛选。
- V87：防重复提交及活动技师/床位约束。
- V88：日报统一所需索引。
- V89：订单、退款及关联流水营业日修正。
- P0：换项目、安排上钟、房态、完成清洁和幂等请求的 400/409 诊断与竞态处理。

## 兼容性与限制

新增数据库对象均为追加式，既有订单默认 `is_historical_backfill=false`；API 既有路径和成功响应保持兼容。真实资源竞争仍可能返回可读的业务 409，这是防止双占用的预期行为。业务写入与离线回执更新之间仍存在进程中断窗口，长期 `PROCESSING` 回执需先核对业务记录再处理。

健康检查和前端缓存版本统一为 `20260912-full-optimization-v1`。
