# 20260915-next-optimization-v5 发布说明

## 本版内容

- 历史补单项目会在同一结算事务内创建 `COMPLETED` 服务单和技师参与记录，并通过 `sales_order_service_session` 关联订单行。
- 订单详情现在显示历史补单的技师、钟类、房间和服务时长，不再把有归属信息的补单行标记为“手工添加项目”。
- 每个补单项目支持 1-4 位技师，后端校验技师不重复且分配比例合计为 100%；前端同步限制最多 4 位。
- 补单继续支持可选房间、15-360 分钟时长及排钟、点钟、选钟、预约钟和加钟类型。
- 补单提成复用普通服务结算的版本化规则和多技师分摊逻辑，退款继续按原订单营业日冲回余额、日报和提成。
- Flyway V94 放宽 `service_session.clock_type` 约束以保存历史加钟归属记录。
- 健康检查和前端静态资源缓存版本统一为 `20260915-next-optimization-v5`。

## 兼容性

- 普通手工添加项目和正常服务单结算仍使用原有请求结构及处理路径。
- 历史补单请求的旧版单技师字段继续兼容；多技师请求最多 4 位。
- V94 只扩展钟类约束，不改写既有服务、订单、支付、钱包或提成数据。
