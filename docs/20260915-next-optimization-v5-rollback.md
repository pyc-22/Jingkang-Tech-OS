# 20260915-next-optimization-v5 回滚指南

## 触发条件

- 健康检查未返回 `UP` 或版本不是 `20260915-next-optimization-v5`。
- 历史补单、订单详情、会员余额支付或退款主流程出现阻断。
- Flyway V94 执行失败。

## 应用回滚

1. 停止新版本服务并隔离流量。
2. 保存故障日志、当前数据库状态和失败请求信息。
3. 从部署前备份恢复上一版 JAR 与完整前端目录。
4. 启动上一版服务，确认健康检查和核心业务恢复。
5. 抽查派钟、正常结算、历史补单、会员余额、退款和日报。

包内 `DEPLOY.ps1` 在切换失败时会恢复其创建的文件备份；数据库仍应使用部署前独立备份作为最终恢复依据。

## 数据库说明

V94 只扩展 `service_session_clock_type_check`，允许保存 `EXTENSION`，不删除或改写既有数据。应用回滚到 v4 时可保留 V94 及其 Flyway 记录。

新版本已经生成的历史补单服务关联属于有效业务记录，不应删除，也不应把约束直接收紧回旧值；已有 `EXTENSION` 服务单会使旧约束恢复失败。

如需数据库时间点恢复，应整体恢复部署前数据库备份，并同时恢复与该时间点一致的 JAR 和前端；不要单独修改 Flyway 历史表。
